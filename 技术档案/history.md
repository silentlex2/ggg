## 5. 平台操作要点（踩过的坑，省你重走）

**控制台 API 怎么调**（前端白屏时的唯一通路）：

```js
const t = localStorage.getItem('console_token');
const H = { 'Authorization': 'Bearer ' + t, 'OperToken': t, 'Content-Type': 'application/json' };
fetch('/console/api/apps/' + APP_ID, { headers: H });
```

- 应用更新用 **`PUT /console/api/apps/{id}`**（POST 会 404），body 含 `name/icon_type/icon/description/use_icon_as_answer_icon`。
- 文件上传 `POST /console/api/files/upload?source=console&_token=<token>`，header 需 `Authorization` + `OperToken`。
- 站点开关 `POST /console/api/apps/{id}/site-enable`，body `{enable_site: bool}`。
- **这个 fork 没有站点记录的保存接口**（站点 description / custom_disclaimer 走 API 改不了，只能等前端恢复后在界面改）。

**站点绑定机制（重要定论）**：

- 平台公开站点执行的是**时间戳版本快照**，不是"最新发布"。
- **市场 fork 出来的应用会被钉死**（工作应用 `f2e4f2a5` 就是），发布/开关站点都不影响它实际执行。
- 普通 `/copy` 应用**跟随最新发布**——公开站点 `35107222` 属于这一类，所以它是可控的。

**已知环境问题**：

- 控制台前端自 2026-10-11 01:40 起**白屏**（平台侧事故），所以一切操作走 API。
- 本机日常 Chrome 打开该站点会**卡在启动 loading**；实测干净浏览器（无头 Edge）渲染完全正常，
  怀疑是日常 Chrome 里某个扩展/广告过滤规则拦截。**不是平台问题，不影响评委**。
- 排查时清过该源 localStorage，`console_token` 已丢失——**要再用控制台 API 需先重新登录一次**。

**平台三项不可用能力**（已在方案里降级处理）：数据库节点（UDMS 超时）、长期记忆库（后端不完整）、
