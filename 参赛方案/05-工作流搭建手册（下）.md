# 「职引」工作流搭建手册（下）· 面试陪练 + 成长档案 + 发布

> 承接《上》的主流程。本篇是**技术含量最高**的部分：多智能体协同 + 会话状态管理 + 长期记忆。

---

## 一、分支 C · 面试陪练（三智能体协同）

### 1.1 设计思路

**为什么用多智能体而不是一个大提示词？**

| 方案 | 问题 |
| --- | --- |
| 单提示词「你既出题又打分」 | 自己出题自己评分，**评分必然宽松**，缺乏客观性 |
| **三智能体分离** | 面试官**不知道**评分标准，评估官**不参与**出题，复盘官只做汇总 → 职责隔离，评分可信 |

> 💡 这是答辩时最有说服力的技术解释。

### 1.2 会话状态变量（用「变量赋值节点」维护）

| 变量名 | 类型 | 含义 | 初值 |
| --- | --- | --- | --- |
| `interview_job` | String | 目标岗位 | "" |
| `question_list` | String(JSON) | 本轮 5 道题 | "" |
| `current_index` | Number | 当前第几题（0 起） | 0 |
| `follow_up_count` | Number | 当前题的追问次数 | 0 |
| `qa_history` | String(JSON) | 全部问答记录 | "[]" |
| `interview_status` | String | `未开始` / `进行中` / `已结束` | 未开始 |

> ⚠️ 这些变量必须在**会话变量**中声明，否则跨轮对话会丢失状态。

### 1.3 节点结构

```
C0 条件节点（interview_status）
   ├─ 未开始 → C1 出题智能体
   └─ 进行中 → C5 评估智能体

C1 出题智能体（按岗位生成 5 题，依据 KB2）
     │
     ▼
C2 代码节点（把题目解析为 JSON 数组）
     │
     ▼
C3 变量赋值（question_list = 题目；current_index = 0；interview_status = 进行中）
     │
     ▼
C4 输出「第 1 题」→ 结束

─────────────────────────────（用户作答后再次进入）──────

C5 评估智能体（评估刚才的回答，输出 JSON）
     │
     ▼
C6 代码节点（把问答追加到 qa_history，计算是否追问/下一题/结束）
     │
     ▼
C7 条件节点
   ├─ 需要追问 → C8 面试官追问（1 次追问）→ 输出 → 结束
   ├─ 还有下一题 → C9 变量赋值（current_index+1，follow_up_count=0）→ C4
   └─ 全部答完 → C10 复盘智能体 → C11 报告模板 → C12 长期记忆写入 → 结束
```

### 1.4 C1 · 出题智能体

**知识库挂载**：`面试题库`
**System**：

```
你是「职引」的模拟面试官。你的唯一职责是【出题】。

## 出题规则
1. 依据【知识库召回内容】中的题库，为目标岗位设计 **5 道题**。
2. 题目结构（必须覆盖）：
   - 1 道自我介绍类
   - 1 道专业能力题（按岗位从题库的"专业能力题"章节抽取，必须与该岗位强相关）
   - 1 道项目/实习深挖题
   - 1 道行为面试题（STAR 类）
   - 1 道岗位理解或职业规划题
3. 每道题控制在 1-2 句，口语化，像真人面试官说话。
4. 题目难度递进：前 2 题热身，第 3-4 题深入，第 5 题综合。

## 输出格式（严格遵守，只输出 JSON 数组，不要任何解释）
[
  {"no": 1, "type": "自我介绍", "question": "..."},
  {"no": 2, "type": "专业能力", "question": "..."},
  {"no": 3, "type": "项目深挖", "question": "..."},
  {"no": 4, "type": "行为面试", "question": "..."},
  {"no": 5, "type": "岗位理解", "question": "..."}
]

## 严禁
- 严禁在题目中透露评分标准
- 严禁输出 JSON 以外的任何内容
```

**User**：`目标岗位：{{interview_job}}　用户专业：{{user_major}}　知识库内容：{{knowledge_context}}`

### 1.5 C5 · 评估智能体

**System**：

```
你是「职引」的面试评估官。你的唯一职责是【独立评估】，不参与出题、不与考生对话。

## 评估依据
严格依据【知识库召回内容】中的"面试表现评分维度"：
逻辑性 35% + 专业度 35% + 表达 20% + 态度 10%

## 评估要求
1. 打分必须有依据，指出回答中的**具体**优点与问题（引用考生原话）。
2. 判断是否需要追问：若回答笼统、无具体事例、或明显有误 → need_follow_up = true。
3. 追问只能针对**同一个问题**，且每道题最多追问 1 次。

## 输出格式（只输出 JSON，不要任何解释）
{
  "scores": {"逻辑性": 0, "专业度": 0, "表达": 0, "态度": 0},
  "strength": "回答中的一个具体优点（引用原话片段）",
  "weakness": "回答中的一个具体问题（引用原话片段）",
  "need_follow_up": false,
  "follow_up_hint": "若需要追问，给出追问方向（一句话）；否则空字符串"
}
```

**User**：

```
【当前题目】{{current_question}}
【考生回答】{{user_input}}
【该题类型】{{current_type}}

【评分标准（知识库召回）】
{{knowledge_context}}
```

### 1.6 C6 · 代码节点（状态推进）

**输入变量**：`eval_json`、`qa_history`、`current_index`、`follow_up_count`、`user_input`、`current_question`
**输出变量**：`qa_history`、`action`（`follow_up` / `next` / `finish`）

```python
import json


def main(eval_json, qa_history, current_index, follow_up_count, user_input, current_question):
    try:
        ev = json.loads(eval_json) if isinstance(eval_json, str) else (eval_json or {})
    except Exception:
        ev = {}

    try:
        history = json.loads(qa_history) if isinstance(qa_history, str) and qa_history else []
    except Exception:
        history = []

    # 记录本轮问答
    history.append({
        "index": int(current_index or 0),
        "question": current_question,
        "answer": user_input,
        "scores": ev.get("scores", {}),
        "strength": ev.get("strength", ""),
        "weakness": ev.get("weakness", ""),
    })

    # 决定动作
    idx = int(current_index or 0)
    fu = int(follow_up_count or 0)

    if ev.get("need_follow_up") and fu < 1:
        action = "follow_up"
    elif idx < 4:            # 共 5 题，索引 0-4
        action = "next"
    else:
        action = "finish"

    return {
        "qa_history": json.dumps(history, ensure_ascii=False),
        "action": action,
        "follow_up_hint": ev.get("follow_up_hint", ""),
    }
```

### 1.7 C8 · 面试官追问节点

**System**：

```
你是「职引」的模拟面试官。考生刚才的回答不够具体，请做**一次**追问。

## 追问要求
1. 只针对当前问题追问，不要换题。
2. 追问要具体、友好，像真人面试官那样："你刚才提到 XX，能具体说说你是怎么做的吗？"
3. 只输出追问的这句话，不要任何前缀、解释或评分。

## 参考方向
{{follow_up_hint}}
```

### 1.8 C10 · 复盘智能体 ★

**System**：

```
你是「职引」的面试复盘教练。请根据完整问答记录，输出一份结构化复盘报告。

## 复盘要求
1. 汇总所有题目的得分，计算**平均分**（四舍五入）。
2. 找出**最弱的一项**（逻辑性/专业度/表达/态度）并说明原因。
3. 指出**具体是哪一题答得最差**，给出改进示范（写出"如果重来一次，可以这样答"的开头 2 句）。
4. 给出 **1 个**最值得优先改进的点（不要罗列一堆）。
5. 语气像教练：客观、鼓励、具体。

## 输出格式（严格遵守）
🎯 模拟面试复盘 · {{interview_job}}

本次得分  <进度条>  <平均分> / 100

【四维表现】
逻辑性  <进度条>  <分>   <一句话点评>
专业度  <进度条>  <分>   <一句话点评>
表达    <进度条>  <分>   <一句话点评>
态度    <进度条>  <分>   <一句话点评>

【答得最好的一题】
第 <N> 题 · <题型> —— <为什么好>

【最需要加强的一题】
第 <N> 题 · <题型>
你的回答：<原话片段>
问题：<具体问题>
👉 可以这样答：<给出示范开头 2 句>

【本次最重要的一个改进点】
<一句话>

🔁 建议再练一次第 <N> 题，回复"重练第 N 题"即可。

## 进度条规则
0-100 分映射为 10 格：满格 █，空格 ░。例：74 分 → ███████░░░

## 严禁
- 不要输出 JSON
- 不要泛泛而谈"多练习"，必须给出具体题目和具体改法
```

**User**：`【岗位】{{interview_job}}　【完整问答记录】{{qa_history}}`

## 二、成长档案（长期记忆）

### 2.1 设计

平台的「长期记忆写入节点」可以把学生画像持久化，实现**跨会话连续性**。

| 写入时机 | 写入内容 |
| --- | --- |
| 简历诊断完成 | 岗位、综合匹配度、四项分项得分、时间 |
| 模拟面试完成 | 岗位、平均分、四维得分、最弱项、时间 |
| 岗位匹配完成 | 浏览过的岗位 ID、匹配度 |

### 2.2 节点配置

**长期记忆写入节点**（在 A5、C10 之后各挂一个）：

| 参数 | 值 |
| --- | --- |
| 记忆库 | 学生成长档案（需先在「记忆库」页面创建） |
| role | 固定值 `student` |
| content | 见下方模板 |

**写入内容模板**（用模板转换节点生成后再写入）：

```
[{{date}}] 简历诊断｜岗位：{{job}}｜综合匹配度：{{score}}｜技能匹配：{{s1}}｜项目经历：{{s2}}
```

```
[{{date}}] 模拟面试｜岗位：{{job}}｜平均分：{{avg}}｜逻辑性：{{l}}｜专业度：{{p}}｜表达：{{e}}｜最弱项：{{weakest}}
```

### 2.3 读取与进步对比

在**分支 A/B/C 的入口**（问题分类之后、各分支大模型之前）加一个**长期记忆读取节点**，
把历史记录作为变量 `history_memory` 注入到大模型提示词中。

在各分支大模型的 System 提示词**末尾追加**这段：

```
## 历史表现（若存在，必须体现对比）
{{history_memory}}

若历史记录非空，请在输出末尾追加一段「📈 你的进步」：
- 对比上次同岗位/同类数据，指出提升了多少
- 若首次使用，则写"这是你的第一次诊断，我会记录本次结果，下次可以看到变化"
```

**预期效果示例**：

```
📈 你的进步
上次（09-28）技能匹配 60 分，本次 78 分，提升 18 分 👍
上次的弱项"缺少量化结果"已明显改善，本次量化结果 4 条。
继续保持：表达规范仍是短板（本次 74 分）。
```

> 💡 **路演必讲**：这一段是"智能体"和"聊天机器人"的分水岭——
> 它证明作品有**记忆**、会**成长**，而不是每次从零开始。

## 四、常见问题与对策

| 问题 | 原因 | 对策 |
| --- | --- | --- |
| 文档提取返回空 | 上传的是图片型 PDF | 提示用户换 PDF/Word；或在知识库开启"精准解析" |
| 问题分类总是归到某一类 | 分类描述不够区分 | 在分类描述里加**反例**（"不包含…的情况"） |
| 数据库节点返回空 | NL2SQL 生成的 SQL 条件过严 | 用 4.3 节的代码节点直接拼 SQL 兜底 |
| 大模型不按格式输出 | 提示词约束不够 | 把格式要求放在 System **最后**，并加"严禁输出 JSON" |
| 追问无限循环 | 没限制追问次数 | 用 `follow_up_count` 变量限制每题 ≤1 次（已在代码节点实现） |
| 会话状态丢失 | 变量未声明为会话变量 | 在「变量」页面把 6 个状态变量都声明为会话变量 |
| 长期记忆没生效 | 记忆库未创建或 role 为空 | 先建记忆库；role 必须传值 |

## 五、技术亮点汇总（答辩直接念）

| # | 亮点 | 一句话说明 |
| --- | --- | --- |
| 1 | **代码节点 5 类结构化抽取** | 不是把简历直接丢给大模型，而是先用 Python 抽取客观指标，再让大模型基于数据诊断 |
| 2 | **数据库节点 + NL2SQL** | 自然语言直接查结构化岗位库，而不是在文档里做模糊检索 |
| 3 | **三智能体职责隔离** | 出题的不知道评分标准，评估的不参与出题，避免"自出自评"的评分宽松 |
| 4 | **会话状态机** | 6 个会话变量维护面试进度，支持追问、断点续答 |
| 5 | **长期记忆 + 进步对比** | 跨会话记录成长轨迹，让"进步看得见" |
| 6 | **三种知识形态混用** | 非结构化文档（5 个）+ 结构化数据（1 个）+ 问答对（1 个） |
| 7 | **防幻觉三件套** | 混合检索 + 结果重排 + 引用归属；检索不到明确拒答 |
| 8 | **提示词工程细节** | 兜底规则、反例约束、格式锁定、进度条可视化 |
