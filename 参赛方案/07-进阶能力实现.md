## 一、A1 · 查询改写 + 多路检索

### 1.1 为什么需要

学生提问是口语化的（"我这个化工的能找到啥工作啊"），直接拿去做向量检索，
和知识库里"化工工艺工程师 岗位职责 必备技能"这类规范表述的相似度偏低，容易召回不到。
**先改写、再多路召回**，是 RAG 的标准进阶做法。

### 1.2 节点位置

```
用户输入 ─▶ 【A1-1 大模型节点：查询改写】─▶ 【A1-2 代码节点：合并去重】
                                                    │
                                                    ▼
                                    知识库检索节点（检索 query = 改写结果）
```

### 1.3 A1-1 · 大模型节点（查询改写）

**输入变量**：`user_input`、`user_major`（可选）
**输出变量**：`rewrite_json`

**System 提示词（全文复制）**：

```
你是检索查询改写器。你的唯一任务是把用户的口语化提问，改写成适合知识库检索的规范查询。

## 改写规则
1. 保留原意，不要增加用户没提到的条件。
2. 补齐领域术语：如"化验"→"质检/分析检测"，"画图"→"AutoCAD 制图"。
3. 输出 1–3 条改写，覆盖不同侧重：
   - 第 1 条：面向"岗位要求/技能"的写法
   - 第 2 条：面向"行业/专业对应"的写法
   - 第 3 条：保留用户原话（兜底用）
4. 每条不超过 30 字，不要写解释。

## 输出格式（严格 JSON，不要任何解释、不要 markdown 代码块）
{"queries": ["<改写1>", "<改写2>", "<改写3>"]}
```

**User 提示词**：

```
【用户提问】{{user_input}}
【用户专业】{{user_major}}
```

> 💡 注意：**用户原话由代码节点自动补进去**（见 1.4），所以即使模型漏了第 3 条也不影响。

### 1.4 A1-2 · 代码节点（合并去重，含原话兜底）

**输入变量**：`user_input`、`rewrite_json`
**输出变量**：`queries`（JSON 数组字符串）、`query_count`

```python
import json
import re


def main(user_input, rewrite_json, max_queries=3):
    base = (user_input or "").strip()

    try:
        obj = json.loads(rewrite_json) if isinstance(rewrite_json, str) else (rewrite_json or {})
        cands = obj.get("queries", []) if isinstance(obj, dict) else []
    except Exception:
        cands = []

    # 原话永远排第一，保证改写失败也不会退化
    seen, out = set(), []
    for q in [base] + [str(c).strip() for c in cands if c]:
        if not q:
            continue
        key = re.sub(r"\s+", "", q)
        if key in seen:
            continue
        seen.add(key)
        out.append(q)

    out = out[:max_queries]
    return {
        "queries": json.dumps(out, ensure_ascii=False),
        "query_count": len(out),
    }
```

### 1.5 两种落地方式（按平台支持能力二选一）

| 方式 | 适用 | 做法 |
| --- | --- | --- |
| **A. 单查询取最优**（推荐先用这个） | 知识库节点只接受一个 query 变量 | 代码节点加一步打分：优先选"第 1 条改写"，因为它最贴检索式；把 `queries[0]` 接到检索节点 |
| **B. 多路召回合并** | 平台支持同一会话里串多个知识库节点 | 每个改写串一个检索节点，再用**代码节点按内容去重合并**（下面这段可直接用） |

**多路合并代码节点**（方式 B）：

```python
import json


def main(hit_1, hit_2="", hit_3=""):
    merged, seen = [], set()
    for block in (hit_1, hit_2, hit_3):
        if not block:
            continue
        items = block if isinstance(block, list) else str(block).split("\n\n")
        for it in items:
            t = str(it).strip()
            if not t:
                continue
            key = t[:60]
            if key in seen:
                continue
            seen.add(key)
            merged.append(t)
    return {"knowledge_context": "\n\n".join(merged[:8])}
```

### 1.6 调参建议

| 参数 | 建议 | 理由 |
| --- | --- | --- |
| 改写条数 | 2–3 条 | 再多收益递减，还拖慢响应 |
| 合并后片段上限 | 8 条 | 对应知识库"最大召回 5" × 多路 |
| 相似度阈值 | 0.45（岗位库可 0.40） | 参见 `知识库/README.md` §2.3 |
| 检索不到时 | **不要硬编**，走 `04` 第六节第 6 条拒答 | 防幻觉底线 |

## 二、A2 · 结构化输出校验 + 重试

### 2.1 问题场景

`04` §4.2（B1 条件抽取）、`05` §1.4（C1 出题）、`05` §1.5（C5 评估）三个节点都要求输出 JSON。
实际运行中最常见的三种异常：

1. 模型把 JSON 包在 ```` ```json ```` 代码块里
2. JSON 前/后多了一句解释（"好的，以下是结果："）
3. 字段缺失或类型不对（`need_follow_up` 返回字符串 `"false"`）

任一发生，下游代码节点 `json.loads` 就抛异常，整个流程断掉——**演示现场最怕这个**。

### 2.2 各节点的 schema 约定（照这张表校验）

| 节点 | kind | 必需字段 | 类型约束 |
| --- | --- | --- | --- |
| B1 条件抽取 | `cond` | `city` `job_type` `major` `industry` `skills` | 前四个为字符串，`skills` 为数组 |
| C1 出题智能体 | `questions` | 数组，每项 `no` `type` `question` | `no` 为 1–5 的整数 |
| C5 评估智能体 | `eval` | `scores` `strength` `weakness` `need_follow_up` | `scores` 为 4 个 0–100 的数，`need_follow_up` 为布尔 |

### 2.3 代码节点（校验 + 清洗 + 截取）

**输入变量**：`raw_output`、`kind`（固定值：`cond` / `questions` / `eval`）
**输出变量**：`ok`（布尔）、`clean_json`（清洗后的 JSON 字符串）、`error`（错误说明）

```python
import json
import re


def _strip_fence(t):
    t = (t or "").strip()
    t = re.sub(r"^```(?:json|JSON)?\s*", "", t)
    t = re.sub(r"\s*```$", "", t)
    return t.strip()


def _extract_json(t):
    """从任意文本里截出第一个完整的 JSON 对象/数组"""
    positions = [i for i in (t.find("{"), t.find("[")) if i >= 0]
    if not positions:
        return None
    start = min(positions)
    open_ch = t[start]
    close_ch = "}" if open_ch == "{" else "]"
    depth = 0
    in_str = False
    esc = False
    for i in range(start, len(t)):
        c = t[i]
        if in_str:
            if esc:
                esc = False
            elif c == "\\":
                esc = True
            elif c == '"':
                in_str = False
            continue
        if c == '"':
            in_str = True
        elif c == open_ch:
            depth += 1
        elif c == close_ch:
            depth -= 1
            if depth == 0:
                return t[start:i + 1]
    return None


def _to_bool(v):
    if isinstance(v, bool):
        return v
    return str(v).strip().lower() in ("true", "1", "yes", "是")


REQUIRED = {
    "cond": ["city", "job_type", "major", "industry", "skills"],
    "eval": ["scores", "strength", "weakness", "need_follow_up"],
}


def _validate(obj, kind):
    errs = []
    if kind == "questions":
        if not isinstance(obj, list) or not obj:
            return ["不是非空数组"]
        for it in obj:
            if not isinstance(it, dict):
                errs.append("数组元素不是对象")
                continue
            for f in ("no", "type", "question"):
                if f not in it:
                    errs.append("缺少字段 " + f)
        return errs

    if not isinstance(obj, dict):
        return ["不是 JSON 对象"]

    if kind == "eval":
        obj["need_follow_up"] = _to_bool(obj.get("need_follow_up"))
        sc = obj.get("scores")
        if not isinstance(sc, dict) or len(sc) < 4:
            errs.append("scores 缺失或维度不足 4 个")
        else:
            for k, v in sc.items():
                if not isinstance(v, (int, float)):
                    errs.append("scores." + str(k) + " 不是数字")

    for f in REQUIRED.get(kind, []):
        if f not in obj:
            errs.append("缺少字段 " + f)

    if kind == "cond" and isinstance(obj.get("skills"), str):
        obj["skills"] = [s for s in re.split(r"[,，、]", obj["skills"]) if s.strip()]

    return errs


def main(raw_output, kind="eval"):
    text = _strip_fence(raw_output)
    body = _extract_json(text)
    if body is None:
        return {"ok": False, "clean_json": "", "error": "未找到 JSON 片段"}

    try:
        obj = json.loads(body)
    except Exception as e:
        fixed = body.replace("“", '"').replace("”", '"')
        fixed = re.sub(r",\s*([\]}])", r"\1", fixed)
        try:
            obj = json.loads(fixed)
        except Exception:
            return {"ok": False, "clean_json": "", "error": "JSON 解析失败：" + str(e)[:120]}

    errs = _validate(obj, kind)
    if errs:
        return {"ok": False, "clean_json": "", "error": "；".join(errs[:5])}

    return {
        "ok": True,
        "clean_json": json.dumps(obj, ensure_ascii=False),
        "error": "",
    }
```

### 2.4 条件节点与重试

```
[A2 校验节点]
   ├─ ok = true  ─▶ 用 clean_json 继续下游
   └─ ok = false ─▶ [A2' 重试：把 error 回灌给原大模型节点，重跑 1 次]
                       └─ 仍失败 ─▶ 用原始文本继续 + 打点记录（不向用户报错）
```

**A2′ 重试时的追加提示（贴在原 System 末尾）**：

```
## 上一次你的输出不符合要求
错误：{{error}}
请严格按上面的 JSON 格式重新输出一次，不要任何解释、不要 markdown 代码块。
```

> ⚠️ **重试只允许 1 次**，避免死循环烧算力。第二次仍失败就走"原始文本继续"，
> 让用户至少能看到内容，而不是看到报错。

### 2.5 答辩怎么说

> "我们把大模型的输出当成**不可信输入**来对待：先用代码节点剥掉 markdown 包裹、
> 截取 JSON、校验字段类型，失败就带着错误信息重试一次。这样下游节点不会因为
> 模型偶尔的格式抖动而整个流程崩掉。"

## 三、A3 · 评分一致性校准

### 3.1 问题场景

三智能体虽然做了职责隔离，但评估官仍可能：

1. 四个维度给**同一个分**（偷懒，没有区分度）
2. 全维度 **90+**（怕打击学生，心态放水）
3. 维度分差 **> 45**（没有认真权衡）
4. 与自述优点/缺点**自相矛盾**（比如 weakness 写"回答笼统"，却给了 95 分）

### 3.2 校准规则

| 规则 | 触发条件 | 含义 |
| --- | --- | --- |
| 无区分度 | 四维标准差 < 3 | 未区分维度或敷衍打分 |
| 疑似放水 | 最低分 ≥ 92 | 全维度高分 |
| 严重失衡 | 最高 − 最低 > 45 | 未仔细评估 |
| 均值异常 | 均值 ≥ 90 或 ≤ 35 | 极端倾向 |
| 逻辑矛盾 | `weakness` 非空 且 均值 ≥ 92 | 指出缺点却给满分 |

### 3.3 代码节点（校准判定）

**输入变量**：`eval_json`（A2 校验后的 `clean_json`）
**输出变量**：`need_review`、`review_reason`、`mean`、`std`

```python
import json
import statistics


def main(eval_json):
    try:
        ev = json.loads(eval_json) if isinstance(eval_json, str) else (eval_json or {})
    except Exception:
        return {"need_review": True, "review_reason": "评估结果无法解析", "mean": 0, "std": 0}

    sc = ev.get("scores") or {}
    vals = [float(v) for v in sc.values() if isinstance(v, (int, float))]
    if len(vals) < 2:
        return {"need_review": True, "review_reason": "有效维度不足，无法校准", "mean": 0, "std": 0}

    mean = sum(vals) / len(vals)
    std = statistics.pstdev(vals)
    lo, hi = min(vals), max(vals)

    flags = []
    if std < 3:
        flags.append("四维分差过小，疑似未区分维度")
    if lo >= 92:
        flags.append("全维度高分，疑似评分宽松")
    if hi - lo > 45:
        flags.append("维度分差过大，疑似未仔细评估")
    if mean >= 90:
        flags.append("均值偏高")
    if mean <= 35:
        flags.append("均值偏低")
    if str(ev.get("weakness") or "").strip() and mean >= 92:
        flags.append("指出了缺点却给满分，前后矛盾")

    return {
        "need_review": bool(flags),
        "review_reason": "；".join(flags),
        "mean": round(mean, 1),
        "std": round(std, 1),
    }
```

### 3.4 复核节点（第二个评估官）

```
[A3 校准] ─▶ need_review = true ─▶ [C5' 复核评估官：更严格标准重评一次]
                                       └─▶ 取两次的**较低分**作为最终分数
[A3 校准] ─▶ need_review = false ─▶ 直接用 C5 原分
```

**C5′ 复核 System 提示词**：

```
你是「职引」的**复核评估官**。上一次评估可能过于宽松，请你独立重新评估。
复核时严格执行：只有能明确引用考生原话作为得分依据的维度才给高分；
回答空泛、无数据、无具体事例的维度，一律不超过 70 分。
输出格式与上一次完全一致（只输出 JSON）。
```

### 3.5 输出话术（**不暴露内部校准**）

用户看到的仍是正常复盘报告，不显示"被复核过"——否则学生会觉得评分不可信。
校准只写进埋点：`review_triggered = true`，路演时用它讲"评分质量有保障"。

## 四、A4 · 埋点统计节点

### 4.1 目的

路演要甩"真实数据"（`00` §9）。平台监测模块只给总量，**意图分布、时段分布、异常次数
得自己埋**。同时它也让"作品真的在被用"这件事可证明。

### 4.2 代码节点（生成一条事件记录）

**输入变量**：`intent`、`user_id`、`conversation_id`、`extra`（可选）
**输出变量**：`event_json`

```python
import json
import datetime


def main(intent, user_id="", conversation_id="", extra=""):
    rec = {
        "ts": datetime.datetime.now().strftime("%Y-%m-%d %H:%M:%S"),
        "intent": (intent or "未知").strip(),
        "uid": str(user_id or "anonymous")[:32],
        "cid": str(conversation_id or "")[:32],
        "extra": str(extra or "")[:80],
    }
    return {"event_json": json.dumps(rec, ensure_ascii=False)}
```

> 🔒 **隐私**：只记 `intent` 与截断后的会话标识，**绝不记录提问原文与简历内容**
> （与 `素材/数据合规与隐私说明.md` 一致）。

### 4.3 落库（两种方案）

**方案 A（推荐，复杂度高、可演示 NL2SQL）**：建 `events` 表，用数据库节点插入。

```sql
CREATE TABLE IF NOT EXISTS events (
  id     INT AUTO_INCREMENT PRIMARY KEY,
  ts     VARCHAR(20),
  intent VARCHAR(20),
  uid    VARCHAR(40),
  cid    VARCHAR(40),
  extra  VARCHAR(100)
);
```

**方案 B（平台不支持写库时）**：把 `event_json` 写进「长期记忆」，定期人工导出统计。

### 4.4 统计查询（直接用于路演截图）

```sql
-- 意图分布
SELECT intent, COUNT(*) AS cnt FROM events GROUP BY intent ORDER BY cnt DESC;

-- 按天活跃
SELECT SUBSTRING(ts, 1, 10) AS day, COUNT(DISTINCT cid) AS sessions
FROM events GROUP BY day ORDER BY day;

-- 异常触发次数（演示"稳定性"）
SELECT extra, COUNT(*) FROM events WHERE intent = '异常' GROUP BY extra;
```

## 五、A5 · 能力雷达文本可视化

### 5.1 输出示例

```
📈 能力雷达（本次 / 上次）

逻辑性  ████████░░  80  ▲+6
专业度  ██████░░░░  62  ─
表达    █████████░  85  ▲+3
态度    ██████████  92  ▲+8

最强：态度（92）　最弱：专业度（62，建议优先补）
```

### 5.2 代码节点（复用于复盘与成长档案）

**输入变量**：`scores_json`（如 `{"逻辑性":80,...}`）、`prev_json`（上次，可为空）
**输出变量**：`radar_text`

```python
import json


def _bar(score, width=10):
    score = max(0, min(100, int(round(float(score)))))
    filled = int(round(score / 100.0 * width))
    return "█" * filled + "░" * (width - filled)


def main(scores_json, prev_json=""):
    try:
        cur = json.loads(scores_json) if isinstance(scores_json, str) else (scores_json or {})
    except Exception:
        cur = {}
    try:
        prev = json.loads(prev_json) if isinstance(prev_json, str) and prev_json else {}
    except Exception:
        prev = {}
    if not isinstance(prev, dict):
        prev = {}
    if not isinstance(cur, dict):
        cur = {}

    lines = ["📈 能力雷达（本次 / 上次）", ""]
    for k, v in cur.items():
        try:
            val = int(round(float(v)))
        except Exception:
            continue
        delta = ""
        if k in prev:
            try:
                d = val - int(round(float(prev[k])))
            except Exception:
                d = 0
            delta = ("  ▲+%d" % d) if d > 0 else (("  ▼%d" % d) if d < 0 else "  ─")
        lines.append("%s %s  %d%s" % (str(k).ljust(4), _bar(val), val, delta))

    if cur:
        try:
            strongest = max(cur, key=lambda k: float(cur[k]))
            weakest = min(cur, key=lambda k: float(cur[k]))
            lines += ["", "最强：%s（%d）　最弱：%s（%d，建议优先补）"
                      % (strongest, int(round(float(cur[strongest]))),
                         weakest, int(round(float(cur[weakest]))))]
        except Exception:
            pass

    return {"radar_text": "\n".join(lines)}
```

> ⚠️ 中文对齐依赖等宽字体；若平台字体不等宽，把 `ljust(4)` 去掉、改用
> `逻辑性：` 这种写法，视觉稍差但不会错位。
