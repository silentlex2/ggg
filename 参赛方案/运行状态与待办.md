## 已知未解缺陷

0. **【平台级】LLM 节点看不到会话历史** —— 三组探针确认：同一 conversation 里，闲聊回「咱们这是刚聊上」、
   面试官回「你上一轮没有提到具体的目标岗位」、岗位匹配回「没看到你之前提到的城市」。
   后果：省略式追问（「那这两个城市哪个更适合我」）必丢条件，黄金集 E5 恒红；"重练第 N 题复读原题"也做不到。
   提示词改不动（v14 试验已验证）。可行修法只有一条：`http-request` + 外部 KV 按 `conversation_id` 存状态。
1. **政策顾问偶发把"分档标准"小标题吞成空行**（正文分档内容正常），属模型输出波动。
2. **更长的闲聊式简历提问仍可能被接待助手接走**（已补兜底，不算故障）。
3. 长答案截断已用 `max_tokens` 修掉（政策 1872 字完整）；平台侧更硬的上限仍未验证。

## 机制结论（仍是现行）

- **站点绑定**：站点绑的是**复制/建站瞬间的草稿快照**。`copy → 改草稿 → publish` 不会让站点跟上，
  必须"**先把草稿改好，再 copy 一次**"。v13 就是这么做的（三跳：v12 → 草稿源 → 正式站）。
- **跨轮次状态传不进去**：会话变量写入不落库、大模型记忆历史从未注入、系统变量取不到
  → 面试状态机只能靠提示词数历史标记（`N = max(M+1, C)`）。
- **5 题制语义**：进度行 `N/5` 是"即将出的题号"，复盘出现在用户下一条消息之后。写断言时别只发 5 条就判失败。
- **不可用能力**：数据库节点、长期记忆库、Python 代码节点、模板转换节点（间歇段错误）。
  新能力一律用 HTTP / 大模型 / 参数提取实现。
- **模型池（2026-10-20 实查）**：`deepseek` 下 chat/reasoner/v4-flash/v4-pro 全 active；
  `openai_api_compatible` 下 kimi-k2.6、deepseek-flash、v4.1-flash；`tongyi` 下 qwen-flash/turbo/plus/max、
  deepseek-v3.2 等 —— 可做降级链，别再以为"只有 v4.1-flash"。
