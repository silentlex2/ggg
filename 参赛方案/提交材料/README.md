# 提交材料存放目录

把要提交的材料**按下面的命名规则**放在本目录，然后运行：

```bash
./tools/pack-submission.sh "队长姓名" "联系方式"
```

脚本会自动检查必需材料是否齐全，并打包成 `提交包-<队长姓名><联系方式>.zip`。

## 命名规则（脚本靠文件名识别）

| 材料 | 命名规则 | 数量要求 | 是否必需 |
| --- | --- | --- | --- |
| 作品提交表 | `作品提交表.pdf`（或多份：`作品提交表-终版.pdf`） | 1 份 | ✅ 必需 |
| 作品演示视频 | `作品演示视频.mp4` | 1 个，**< 3:00** | ✅ 必需 |
| 团队活动记录·图片 | `团队活动-01.jpg`、`团队活动-02.jpg` … | **≥ 3 张** | ✅ 必需 |
| 团队活动记录·视频 | `团队活动记录.mp4` | ≥ 30 秒 | ⚠️ 官方要求，建议补 |
| 作品截图 | `作品截图-01.png` … | 3–5 张 | 建议 |
| 其他（工作流编排图、监测数据图等） | 任意 `*.png` / `*.jpg` | — | 可选 |

## 各材料的来源

| 材料 | 怎么产出 |
| --- | --- |
| 作品提交表 PDF | 用 `02-提交材料清单.md` 的三份**正式稿**（草稿 A/B/C）填入官方模板 docx（在 `site-dump/assets/files/` 里），另存为 PDF |
| 作品演示视频 | 按 `01-路演与答辩.md` §一 分镜 + §四 逐字旁白稿录屏 |
| 团队活动记录 | **从第一天就开始随手拍**（`03` §3.3 提醒）：开发过程、测试现场、同学试用 |
| 作品截图 | 平台上的**真实运行界面**（不是原型！优先级见 `02` §二） |

> ⚠️ 本目录内容**不会被 git 提交**（见仓库根 `.gitignore`），避免大文件与个人信息进仓库。
