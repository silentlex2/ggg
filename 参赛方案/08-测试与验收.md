### 1.3 异常兜底（8 条，对应 `04` 第六节）

| --- | --- | --- | --- |

### 1.4 面试全流程（1 条，12 步走完）

| 步 | 操作 | 期望 |
| --- | --- | --- |
| 1 | 说"来一场化工工艺工程师的模拟面试" | 进入模拟面试，先锁定本轮契约，再出第 1 题（进度 1/5） |
| 2 | 第 1 题敷衍作答（"就那样吧"） | 评估官判定需追问，面试官追问 1 次 |
| 3 | 补充回答 | 按契约判定后进入第 2 题，进度 2/5→3/5（补答追问时进度取 `max(M+1, C)`，不会被拉回第 1 题） |
| 4–9 | 依次答完第 2–5 题 | 每题只追问 ≤1 次 |
| 10 | 答完第 5 题 | 输出复盘报告（四维分项 → 加权算式 → 本次得分，顺序不能反） |
| 11 | 回复"重练第 3 题" | 直接重出第 3 题，进度行显示「重练 · 第 3 题」（**不打折**） |
| 12 | 重新作答第 3 题 | 立刻重出完整复盘（四维 → 算式 → 得分），该题按新答案重判，进度计数不倒退、不重复计分 |

| # | 操作 | 期望 |
| --- | --- | --- |

### 1.7 黄金集回归（自动化，46 条）

> **站点定稿后每改一次配置都要重跑这一套**，它是对外口径的唯一客观依据。
> 用例集 `技术档案/eval_cases.py`，执行器 `技术档案/eval_golden.py`；一键门禁 `技术档案/run_all.py` 把巡检与黄金集串在一起。

**按组构成**（`--workers 3`，v19 正式站实测 157.5s）：

| 组 | 条数 | 考什么 | 典型用例 | v19 实测 |
| --- | --- | --- | --- | --- |
| A 意图分类 | 8 | 分类器把话分到对的功能 | 「帮我看看我的简历有什么问题」（应走简历诊断） | 8/8 |
| B 边界 | 12 | 方法类提问不开面、能力外请求不硬答 | 「面试被问到期望薪资应该怎么答」（应给方法，**不出题**） | 12/12 |
| C 拒答 | 6 | 越界请求明确拒绝、不出现禁用话术 | 「帮我直接写一份简历」（应拒代写并给替代路径） | 6/6 |
| D 异常 | 6 | 全角空白、重复词、超长输入不崩 | 200 个「简历」 | 6/6 |
| E 多轮 | 8 | 换轮次后条件不丢、进度不串台 | 「那这两个城市哪个更适合我」 | **7/8** |
| F 跨专业不臆测 | 6 | 给非化工专业的学生，不许冒出化工名词 | 会计 / 机械 / 计算机 / 材料 / 英语 / 体育各问一次岗位匹配 | **6/6** |

**指标与门槛**：

| 指标 | 含义 | 门槛 | v19 实测 |
| --- | --- | --- | --- |
| `SCORE` | 全部用例通过率（退出码 0 = ≥ 0.80） | ≥ 0.80 | **0.957**（44/46） |
| `ROUTE_ACCURACY` | 路由准确率（用签名正则**反推实际走了哪条分支**，不看模型自述） | ≥ 0.85 | **1.000** |
| `CONTENT_PASS` | 内容命中率（must / must_not 关键词） | ≥ 0.80 | **0.957** |
| `REFUSAL_PASS` | 拒答通过率 | 6/6 | **6/6** |

**E5 是唯一的恒定红项，而且是刻意保留的哨兵。** 平台不给 LLM 节点注入对话历史（三轮独立探针证实），
所以省略式追问「那这两个城市哪个更适合我」在本轮上下文里必丢城市。要让它变绿只有两条路：
① 提示词层硬记——v14 实测反而诱发臆测（给化工学生套机械专业），已回滚；
② 把状态传进去——v19 已用 `ctx` 通道让**自建前端**补上历史，但平台原生站点不传，仍然红。
宁可留着这条红，也不放松断言去凑满分：它测的正是产品的真实短板。

用法：`python 技术档案/eval_golden.py [站点码] [--json 输出路径] [--only 意图,边界] [--workers 3]`。
`--workers` 不要超过 3：并发 6 会把平台压到排队，单例耗时从 ~160s 涨到 120–280s，还出现过 0 字符超时（SCORE 虚降到 0.825）。
输出末尾是固定契约，便于 CI 抓取：

```
---SCORE_SUMMARY---
SCORE: 0.975
ROUTE_ACCURACY: 1.000
CONTENT_PASS: 0.975
REFUSAL_PASS: 6/6
CASES: 40
SITE: YnmaDNCRpd1otyrC
---END---
```

**46 条里另一条红项（A3）是偶发**：面试开场时，面试官约十分之一的次数只给「第 1 题 · 自我介绍」，
不给「📊 面试进度：1/5」那一行。断言要求进度行必须在，所以判红——这是**平台侧输出不稳定**，
不是断言写错。自建前端已加兜底：拿不到进度行时从「第 N 题」反推（见 `前端/README.md`）。

**为什么刻意偏向边界**：46 条里 38 条是边界、拒答、异常、多轮、跨专业，纯正常问答只有 8 条。
只考正常路径会得到一个虚高的分数——真正会被评委问倒的是「面试技巧怎么答」「帮我写简历」这类越界请求。
（做法参考 career-ops 的 `evals/`：指标是**与参考标签的一致度**，不是绝对正确性。）

**材料侧还有一条静态检查**（离线可跑，不需要站点）：

```bash
python 参赛方案/tools/check-links.py        # 扫 参赛方案/ 与 交接说明.md 的 Markdown 相对链接
python 参赛方案/tools/check-links.py --all  # 连 技术档案/ 与 前端/ 一起扫
```

形式审查最常见的翻车不是内容不行，而是材料里引用的文件根本不存在（改名、挪目录、从没产出过）。
这个脚本只看 `[文字](路径)` 语法、不猜反引号里的示意路径，实测 39 个文档 / 48 条链接 / 死链 0。

**其他已跑通的自动化脚本**（都在 `技术档案/`，用法 `python <脚本> <站点码>`）：

| 脚本 | 覆盖 | v19 结果 |
| --- | --- | --- |
| `healthcheck.py` | 五分支巡检（闲聊 / 政策 / 岗位 / 面试 / 简历），退出码 0 = 通过 | **5/5** |
| `probe_v9.py` | 简历诊断六项断言（矩阵表头 / 判定符号 / 覆盖度行 / 硬门槛结论 / 隐私遮罩 / 优先改缺口） | **6/6** |
| `probe_retry.py` | 重练闭环（开面 → 答满 5 题 → 出复盘 → 重练第 3 题 → 重答必须立刻重出完整复盘） | **OK** |
| `probe_v7d.py` | 面试收尾 / 重练不打折 / 政策拒答给路径 | **OK** |
| `probe_e2e.py` | 16 条端到端用例（意图 / 岗位 / 异常 / 面试闭环） | 意图 9/9、岗位 4/4、异常 2/2 |
| `probe_interview_trace.py` | 逐轮打印面试进度与题型，直到出复盘 | 1/5→5/5，第 6 轮出复盘 |
| `h5_responsive.js` | 自建前端五档视口布局回归（320/390/768/1024/1440），只测量不发请求 | **5/5，溢出 0px** |
| `demo_h5.js` | 演示动作脚本化（问诊/岗位/面试），存可拍状态截图并记耗时 | 问诊 1.6s / 岗位 13.8s / 面试 10.3s |
| `probe_ncss.py` | 政策实时源体检：本机能否直连 ncss.cn + 线上政策分支是否吐带日期条目 | 本机 200/0.2s；线上 796 字、**6 条带日期**、提到国家大学生就业服务平台 |

⚠️ **5 题制的固有语义**：进度行「N/5」是**即将出的题号**，答完第 5 题时最后一条消息仍是「第 5 题 / 5/5」，
复盘出现在**用户下一条消息之后**。写自动化断言时不要只发 5 条作答就判失败。
