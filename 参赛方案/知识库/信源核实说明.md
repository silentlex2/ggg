## 三、岗位数据（KB4）的声明与用法

- KB4 是 **65 条示例岗位**，用于演示"岗位匹配"的检索与打分链路，**不是实时招聘数据**。
- 文件头与知识库说明里均已写明"数据为示例数据，实际岗位以学校就业网发布为准"，智能体回答时也会带免责提示。
- **答辩建议口径**："岗位库目前是示例规模（65 条）用于验证链路，正式落地时把学校就业网的岗位数据接进来即可，结构已经按真实 JD 字段设计（专业要求、必备技能、加分技能、城市、学历…）。"

---

## 四、隐私与合规边界（与《数据合规与隐私说明》一致）

- **不接入**校园内网系统（教务、学工、就业系统），**不抓取**任何非公开数据。
- 简历**原文只用于当次会话的推理与建议**，不写长期记忆、不进埋点与日志、不做二次使用
  （上传的文件由平台按会话保存；当前版本长期记忆未启用）。
- 政策与岗位回答均**附来源与免责**，并提示"以官方最新通知为准"。

## 五、可复现的核实方法（评委若追问）

1. 打开 `www.cq.gov.cn` 或 `rlsbj.cq.gov.cn`，搜索本文档第二节表格中的**文号**（如"渝人社〔2024〕242 号"）；
2. 对照 KB5 中该补贴的**对象、标准、申领渠道**三项；
3. 若官方已更新，以官方最新文件为准——知识库中已内置该提示语。

## 三、实时信源（2026-10-14 新增）

「职引」的政策咨询分支里内置了一个 **HTTP 节点**，用户提问政策时，工作流会**当场联网**向
**国家大学生就业服务平台**（教育部主管，`www.ncss.cn`）的公开接口取一次最新就业政策动态，
连同知识库内容一起回答。这解决的是"知识库会过期、但政策必须新鲜"的问题。

| 项 | 内容 |
| --- | --- |
| 数据源 | 国家大学生就业服务平台（教育部主管，域名 `www.ncss.cn`） |
| 接口 | `GET /student/api/news/list?limit=6`（公开接口，无需鉴权） |
| 返回 | JSON 数组，字段：`title` 标题 / `displayDate` 发布日期 / `link` 原文链接 |
| 体积 | 约 1.4 KB，足够小，不会挤占模型上下文 |
| 平台侧稳定性 | 实测 **20/20 成功**（HTTP 节点不走沙箱，是平台上最稳的一类节点） |
| 回答呈现 | 用户在问"最近有什么新政策"时，会看到 3–5 条**带发布日期**的动态，来源标注为"国家大学生就业服务平台（www.ncss.cn）实时数据" |

**离线快照**：`知识库/快照/ncss-news.json`（30 条）与 `知识库/快照/ncss-corp.json`（招聘企业列表），
抓取于 **2026-10-14**，留作"这个接口确实能取到真数据"的存档证据。

**边界说明（如实）**：
- 实时源只用于**政策动态**这一路；具体补贴标准、办理流程仍以 KB5 的政策原文为准，避免实时接口内容偏差影响硬性数字。
- 平台**不能**实时取回"岗位级"数据——该平台需要登录才开放职位接口，所以岗位匹配仍然走 KB4 示例库并已明确声明。
