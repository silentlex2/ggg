# KB1 · 简历写作规范库

> 用途：「职引」简历诊断模块的**评判依据**。上传到智小理知识库，供检索节点召回。
> 建议分段方式：按 `##` 标题自动分段；最大分段长度 800 tokens；重叠 15%。

---

## 一、简历整体结构规范

### 1.1 必备模块（缺一即扣分）

| 模块 | 是否必备 | 说明 |
| --- | --- | --- |
| 个人信息 | 必备 | 姓名、手机、邮箱、求职意向 |
| 教育背景 | 必备 | 学校、学院、专业、学历、起止时间 |
| 专业技能 | 必备 | 与目标岗位相关的技能清单 |
| 项目/实践经历 | 必备 | 至少 1 段，建议 2–3 段 |
| 荣誉奖项 | 建议 | 有则写，无则省略 |

### 1.2 可选模块（按岗位取舍）

- **实习经历**：有实习务必单列，优先级高于校内项目
- **校园经历**：学生干部、社团、志愿服务，适合职能类岗位
- **科研经历**：论文、专利、竞赛，适合研发/科研类岗位
- **自我评价**：**不建议写**，除非能写出具体差异化内容；空泛的自我评价是减分项
- **作品集链接**：设计、开发、新媒体类岗位强烈建议附上

### 1.3 篇幅与格式

- **篇幅**：本科生**一页**为佳，最多两页；超过两页必须精简
- **格式**：统一导出 **PDF**；文件名格式 `姓名-岗位-学校.pdf`
- **字体**：中文用宋体/思源黑体，英文用 Calibri/Times New Roman，正文 10–11pt
- **颜色**：正文黑色，最多一个强调色；不要花哨模板
- **对齐**：时间右对齐，模块标题加粗并加分隔线

## 二、表达规范（诊断的核心规则）

### 2.1 STAR 法则

每段经历按四要素展开：

| 要素 | 含义 | 反例 | 正例 |
| --- | --- | --- | --- |
| **S**ituation | 背景/问题 | 「参与了项目开发」 | 「针对实验室数据记录依赖纸质台账、易出错的问题」 |
| **T**ask | 你的任务 | 「负责一部分工作」 | 「负责设计并实现数据自动采集与校验模块」 |
| **A**ction | 你怎么做 | 「用了 Python」 | 「用 Python + pandas 搭建 ETL 流程，设计 12 条数据校验规则」 |
| **R**esult | 结果（**必须量化**） | 「效果不错」 | 「台账录入时间从每天 40 分钟降至 5 分钟，数据错误率降为 0」 |

### 2.2 量化优先原则

**凡是能数字化的，一律数字化。** 常用量化维度：

- 时间：耗时从 X 降至 Y、周期缩短 X%
- 规模：处理数据 X 万条、服务用户 X 人、代码 X 行
- 比例：效率提升 X%、准确率 X%、覆盖率 X%
- 排名：年级前 X%、竞赛第 X 名（共 X 支队伍）
- 金额/成本：节省成本 X 元

> ⚠️ 没有量化结果的经历，评分上限为该项满分的 **60%**。

### 2.3 动词开头

每条经历用**强动词**开头，禁止用「负责」「参与」单独开头（太虚）。

| 弱表述 ❌ | 强表述 ✅ |
| --- | --- |
| 负责数据分析 | 建模并分析…、清洗并统计… |
| 参与项目开发 | 独立实现…、主导设计… |
| 协助老师做实验 | 设计正交实验方案并完成 24 组平行实验 |
| 学习了 Python | 用 Python 完成…（用产出证明） |

**推荐动词库**：
- 技术类：设计、实现、搭建、重构、优化、部署、调试、集成、封装
- 分析类：建模、统计、分析、评估、验证、对比、预测
- 组织类：策划、统筹、协调、组织、主持、推进
- 成果类：提升、降低、缩短、节省、达成、突破

### 2.4 禁止出现的表述

- 「熟悉/了解/掌握」单独成句而无证据
- 「认真负责、吃苦耐劳、团队协作能力强」等空话
- 「参与了」「协助了」而不说明**具体做了什么**
- 与目标岗位无关的经历占大篇幅
- 虚构经历、夸大职级（一旦面试被追问会崩）

## 三、各模块详细写法

### 3.1 个人信息

- 必填：姓名、手机号、邮箱、求职意向（**必须写**，否则 HR 不知道你要投什么）
- 选填：政治面貌（国企/事业单位建议写）、籍贯（本地企业可写）
- **不要写**：身份证号、家庭住址、婚育状况、身高体重

### 3.2 教育背景

- 格式：`2022.09–2026.06　重庆理工大学　化学工程与工艺　本科`
- **必写 GPA/排名**（若在前 30%）；否则写核心课程成绩
- 主修课程只列**与岗位相关**的 5–8 门
- 若有双学位、辅修、交换经历，在此说明

### 3.3 专业技能

按**熟练度分层**，并给出证据：

```
熟练：Aspen Plus（完成 3 个工艺流程模拟）、AutoCAD
掌握：Python（pandas/numpy 数据处理）、Origin 数据分析
了解：SQL、Git
```

- 语言能力：CET-4/6 分数（>500 可写）、其他语种等级
- 证书：写明**取得时间**与**等级**
- **禁止**写「Office 办公软件」这类无区分度的技能

### 3.4 项目/实践经历（简历主体，占篇幅 50%+）

每条经历的标准结构：

```
项目名称 | 角色 | 起止时间
· 【背景】一句话说明要解决什么问题
· 【行动】用 2–3 条说明你具体做了什么（动词开头 + 技术/方法）
· 【结果】量化结果，1 条
```

**按岗位类型的侧重**：

| 岗位类型 | 应突出的内容 | 关键词示例 |
| --- | --- | --- |
| 工艺/化工工程师 | 工艺流程、物料衡算、设备选型、安全规范 | 精馏、反应器、Aspen、HAZOP、GB 标准 |
| 研发工程师 | 实验设计、表征手段、数据分析、文献调研 | 正交实验、XRD/SEM、Origin、机理分析 |
| 质检/分析 | 检测方法、仪器操作、标准规范 | HPLC、GC、滴定、国标方法、偏差分析 |
| 生产管理 | 排产、成本、良率、现场改善 | 良率提升、5S、精益、OEE |
| 数据/IT 类 | 编程语言、算法、工程化 | Python、SQL、模型、接口 |
| 职能类 | 组织协调、数据统计、流程优化 | 统筹、SOP、覆盖率 |

### 3.5 荣誉奖项

- 按**含金量**排序，不按时间
- 格式：`2024.10　国家励志奖学金（年级前 5%）`
- 同一类奖项合并写：`校级奖学金 3 次（2023–2025）`
- 只写校级及以上；院级奖项可省略

## 四、20 个常见硬伤（诊断规则清单）

诊断时逐条检查，命中即列出：

| # | 硬伤 | 判定方法 | 修改建议 |
| --- | --- | --- | --- |
| 1 | 无求职意向 | 个人信息区未出现岗位名称 | 补充明确的求职意向 |
| 2 | 无联系方式或邮箱不正式 | 缺手机/邮箱，或用 QQ 昵称邮箱 | 补充；邮箱用 `姓名拼音@` 形式 |
| 3 | 篇幅超两页 | 页数 > 2 | 删减与岗位无关内容 |
| 4 | 项目经历无量化结果 | 该段无任何数字 | 补充量化结果 |
| 5 | 通篇「负责/参与」开头 | 出现频次 > 3 | 改用强动词 |
| 6 | 无 STAR 结构 | 只有罗列，无背景-行动-结果 | 按 STAR 重写 |
| 7 | 技能与岗位不匹配 | 岗位要求技能未出现 | 补充岗位关键词 |
| 8 | 岗位关键词缺失 | 对照 JD 比对，命中率 < 50% | 按 JD 补关键词 |
| 9 | 空泛自我评价 | 出现「认真负责/吃苦耐劳」 | 删除或改为具体事实 |
| 10 | 排版不统一 | 字号/缩进/项目符号混乱 | 统一模板 |
| 11 | 时间倒序错误 | 经历未按时间倒序 | 调整为倒序 |
| 12 | 错别字/中英标点混用 | 逐字检查 | 修正 |
| 13 | 无教育背景成绩 | 未写 GPA 或排名 | 补充（前 30% 必写） |
| 14 | 技能熟练度不可验证 | 「熟悉 X」但无证据 | 补充使用场景或产出 |
| 15 | 无关经历占篇幅过大 | 与岗位无关内容 > 40% | 精简或删除 |
| 16 | 项目描述只有技术堆砌 | 罗列技术但无问题与结果 | 补充业务价值 |
| 17 | 一页塞满无留白 | 行距 < 1.15，边距过窄 | 调整留白 |
| 18 | 简历为 Word 格式 | 文件后缀为 .doc/.docx | 导出为 PDF |
| 19 | 文件命名不规范 | 文件名非「姓名-岗位」 | 重命名 |
| 20 | 证件照不合适 | 生活照/自拍 | 换为正式证件照或删除 |

## 六、诊断打分规则（供大模型节点使用）

**综合匹配度 = 技能匹配 40% + 项目经历 30% + 表达规范 20% + 排版格式 10%**

| 维度 | 满分条件 |
| --- | --- |
| 技能匹配 | 岗位必备关键词命中率 ≥ 85% |
| 项目经历 | 有 2 段以上，均含 STAR + 量化结果 |
| 表达规范 | 无空话、动词强、无硬伤 ≥ 3 条 |
| 排版格式 | 一页、PDF、字体统一、命名规范 |

**输出要求**：
1. 给出综合匹配度（0–100）
2. 给出四项分项得分
3. 给出**按影响排序的 3 条优先改进建议**（不要罗列 20 条）
4. 每条建议标注依据来源
