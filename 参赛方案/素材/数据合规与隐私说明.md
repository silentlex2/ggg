# 「职引」数据合规与隐私说明

> 用途：① 答辩必问「学生简历的隐私怎么保障」的标准答案；② 可直接摘进作品提交表的"技术实现"一节。
> 这份说明同时也约束了实现——**代码和节点配置必须与本文一致，不能只写在材料里**。

---

## 一、数据来源与合法性

| 数据 | 来源 | 合法性说明 |
| --- | --- | --- |
| 岗位库（KB4） | 校内招聘会公开信息、企业公开招聘信息 + 团队手工整理 | 均为公开发布信息，不含任何内部系统数据 |
| 就业政策库（KB5） | 国家及学校官网公开文件 | 公开政策文本 |
| 简历写作规范（KB1） | 公开资料整理 | 通用写作规范，无版权争议 |
| 面试题库（KB2） | 公开题库整理 | 通用面试题 |
| 专业-行业-岗位对照（KB3） | 学校公开专业目录、就业质量报告 | 公开信息，已脱敏 |
| 高频问答（KB6） | 公开资料 + 团队沉淀 | 不含个人信息 |

**明确不做**：不接入校园内网系统（教务、学工、就业系统），不抓取任何非公开数据。

---

## 二、学生简历的处理方式（核心）

| 环节 | 处理方式 |
| --- | --- |
| 上传 | 通过平台的文件上传接口传入，仅用于**当次推理**：解析出结构化指标（字数、技能命中、量化条数、模块识别等）并对照岗位要求 |
| 存储（平台侧） | **文件由星辰平台按会话保存**（这是平台行为，不是我们额外建库） |
| 存储（我们侧） | 不新建任何数据库、不落任何自有存储；原文不写入长期记忆、不写入埋点、不写入任何日志节点 |
| 使用范围 | 只用于当次会话里的诊断与建议；**不用于模型训练，不做二次使用** |
| 长期记忆 | **未启用**（平台后端不完整，已主动降级为单会话内记忆窗口） |
| 展示 | 诊断结果**仅本人会话内可见**，不对外公开、不用于展示 |
| 删除 | 学生点「新对话」即清空本地会话与会话上下文；平台侧会话记录可在控制台按会话删除 |

> ⚠️ **实现红线**（设计约定）：简历正文由「文档提取」节点解析后，只连到简历分支的大模型节点；
> 唯一的外部请求节点（政策实时源）取不到它，也不在简历分支上。
> **不得**把原文写入长期记忆、埋点或任何日志节点——这是「不进长期记忆、不做二次使用」的兑现点。
> 当前版本没有启用长期记忆与埋点节点，原文只进当次模型上下文。

> 📌 **口径校准（2026-10-20）**：本节此前写的是"不留存简历原文 / 会话结束即释放"。
> 这句话不准确——上传的文件是**平台按会话保存的**，我们无权声称它不被存储。
> 现已改为可核验的表述：**平台按会话存文件，我们不进长期记忆、不进埋点、不做二次使用、不用于训练**。
> 答辩被追问时按这一版答，不要再说"完全不落库"。

---

## 三、对用户的承诺（可写进作品使用说明）

1. 我们不把你的简历原文写进长期记忆、埋点或日志，不用于模型训练，也不做二次使用；
   上传的文件由平台按会话保存，你随时可以清空会话。
2. 你的诊断报告只在你自己的会话里可见。
3. 我们不提供虚构经历的模板，也不代写简历——只做诊断与建议。
4. 岗位与政策信息来自公开渠道，仅供参考，最终以官方发布为准。

---

## 四、边界与免责

- 岗位库为**示例规模**（65 条），不承诺覆盖全网岗位；数据截至 **2026-09**。
- 政策类回答均附来源，并以"具体以学校官网及国家最新规定为准"收尾。
- 智能体**不替代**就业指导老师，定位是**高频问题分流**：标准化问题交给智能体，
  深度个性化问题仍由老师处理。
